# 思绪盒子 Thoughts Box

> 本地优先的个人思绪整理工具 —— 把杂乱的念头、经历、情绪倒进盒子，整理后，盒子里放满了过去的瞬间。
>
> A local-first personal tool for capturing and re-organizing messy thoughts, episodes and emotions.

**项目状态**：V 0.X 版本——记录、脱敏、整理、回看的核心闭环已完成；更多规划和功能正在逐步迭代

## 这是什么

Thoughts Box 是装在你自己电脑上的一个私人盒子，专门接住那些还没想清楚、乱糟糟的念头、经历和情绪。你不必先想好格式或分类，只管往里倒；**脱敏、整理、回看、隐私把关**这几件事，交给它帮你做，而且每一步你都看得见、点头了才算数。它能帮你：

- **先保护再离开本机**：记录里的姓名、电话、地点等敏感内容，可先在本机识别出来、换成不含原义的占位符。只有你选了云端整理，内容才可能外发；发之前应用会把「真正会被发出去的那一段」整段摆给你看，逐条点确认才发送。不使用云端，内容就永不外发。
- **万千思绪理成结构**：应用依据一套公开的情绪、主题、实体词表，把自由文本关联成可浏览的结构；记录之间的「可能相关 / 疑似同一」也能连成关系、把候选实体转正。所有自动结果默认只是**候选**，你确认后才成为正式内容；你的手工修改永远优先，不会被机器重算覆盖。
- **回看一个个情绪的瞬间**：情绪 / 经历 / 念头 / 人物与事物 / 主题，五个维度各成一页，每条都能追回它出自哪条记录的哪一句。情绪盒子——出现过的情绪按频次凝成一颗颗水晶球、静静地摆在盒子里，触碰就能看到当初往日情景。
- **从容确认不被催**：写一条与「复核它是否合格」是分开的两件事。待复核的内容是一份只读清单，能一次确认多条、能看到某条已经搁了多久还没整理；睡前收尾只管倒出来、收好，不必在意还有多少条。
- **随时写，随手收**：写一条随时可用，可选「保存并整理」；数据始终是你自己的——所有记录存在本机，无账号、无云依赖，备份、导出、导入、整库恢复都在应用内完成。

## 处理模式与隐私边界

每条记录你都可以选一种**整理方式**，它决定内容会不会离开本机、以及离开前怎么处理：

| 整理方式 | 会发生什么 | 内容外发 |
|---|---|---|
| **仅保存** | 只把原文存下来，不整理、不脱敏 | 从不 |
| **本地模型** | 由你本机 / 局域网自建的模型服务整理，先用脱敏文本再分析 | 从不 |
| **云端（本地脱敏）** | 先在本机把敏感内容脱敏（本地模型识别），只把脱敏后的文本发给云端模型整理 —— **推荐的云端方式** | 仅脱敏文本，需逐条授权 |
| **云端（原文发送）** | 不脱敏，直接把原文发给云端模型整理，需你明确选择并逐条授权 | 原文，需逐条授权 |

### 云端整理时，内容是怎么走的

以「云端（本地脱敏）」为例，完整流程是这样：

1. 你写一条记录，选好整理方式并保存。
2. 本机先把姓名、电话、地点等敏感内容识别出来、换成占位符 —— 这一步只在本机发生，原文不动，也不上传。可选择让本地模型来识别，或由你手动标记。
3. 发送前，应用把**真正会被发出去的那段已脱敏的文本**整段摆给你看：你看到的就是云端将看到的，没有黑箱。
4. 你点「本次发送」，授权只对**这一条、这一个版本**有效；内容或脱敏方式一变，旧授权自动作废，要重新看过再确认。
5. 云端只拿到脱敏文本做整理，回来的情绪、主题、关联先作为**候选**呈现，你采纳后才成为正式内容。
6. 全程可反悔：可以强制重跑脱敏、撤回采纳；不点确认，什么都不会离开本机。

整理与脱敏都在后台任务里进行，界面能看进度、能取消在途任务，失败会单独列出来而不混进正常结果。

关于删除：删除是真的抹掉本机记录（连带搜索索引），并留下一条不含原文的痕迹；但旧备份不会被自动回溯改写，物理介质上也可能恢复，需要用户自己处理。

## 运行要求

- Node.js `>=24.18.0 <27`（版本过低或过高都会在启动自检中被明确拒绝）。
- 主要开发于 Windows；macOS / Linux 走 XDG 数据目录，不硬编码路径。

## 安装与启动

普通用户装好依赖、一条命令即可，浏览器打开就能用：

```bash
npm install
npm run dev       # 同时启动本地后端（8737）和前端（5173）
```

也可以：

```bash
npm run launch    # 同上；若配置了本机模型服务的 key，会自动接上真实整理链路
```

数据、配置都在本机，不用注册账号、不用联网。两个端口是固定的，被占用时会明确报错而不是悄悄换端口 —— 这样不会意外起两个实例、绕过单实例保护。

### 开发者相关

以下命令面向开发、排错或只想看界面，日常使用不需要：

```bash
npm run typecheck     # 服务端 + 前端两套类型检查
npm test              # 全部验收断言（本快照约 91 个测试文件）
npm run build         # 生产构建
npm run start:server  # 只起后端
npm run start:web     # 只起前端
npm run start:mock    # 5174，用 fixtures/ 演示数据看界面，无需后端 / 数据库 / 模型 key
```

- 没有后端也想看界面时用 `npm run start:mock`；它只在开发构建生效，生产构建会把整条假数据链路（连同 `fixtures/`）摇掉，不进入产物。
- 这些启动器都是 `node scripts/*.mjs`，Windows / macOS / Linux 同一条命令，跨平台的环境变量设置由脚本内部处理。
- 测试与多实例开发请用 `TB_DATA_DIR=<目录>` 隔离数据目录（见下节），不要碰真实用户数据。

## 数据在哪

- 运行时数据目录：`%LOCALAPPDATA%\ThoughtsBox\`（非 Windows：`$XDG_DATA_HOME` 或 `~/.local/share`）。
- 数据库、备份、日志、本地配置、实例锁都在该目录，**仓库目录不放私人数据**。
- 用 `TB_DATA_DIR=<目录>` 覆盖 —— 测试与多实例开发必须用它隔离。
- 首次启动会从 `config.example.json` 生成本地配置；模板只有占位值，密钥只经环境变量提供。启动时还会做一次自检（版本、迁移、目录布局等），任一不过就拒绝启动而非带病运行。

## 项目原则

- **本地优先**：记录、整理结果、回看、搜索全部存在本机 SQLite，服务只监听回环地址，固定端口，不自动切换。
- **云端是显式选项**：每条内容单独选整理方式；发往云端前必须经过逐条的「本次发送授权」，并向用户展示真实脱敏文本。不使用云端则永不外发。
- **删除是真的删除**：见上文隐私边界一节；声明只承诺做得到的事。
- **AI 是建议者，不是裁决者**：自动产生的情绪、主题、实体关联先进入候选与建议队列，由用户确认后才成为正式内容；用户的手工修正优先于任何重算。
- **封闭取值**：状态、关系类型、处理方式、实体类型等取值集合固化在 `src/shared/constants/enums.json`，由 Schema 校验与测试断言共同守护，实现不得发明取值。
- **关系是第一类对象，全局图谱推迟**：记录之间的关联以「可能相关 / 疑似同一」候选进入关系契约，由人在「待确认」里裁决，候选实体可转正、转正后关系写入图谱；跨记录的全局自动图谱（自动推断未知关联）已裁定推迟，不是被遗漏了。

## 仓库结构

```
src/server/   本地后端：HTTP 服务与路由面（records / ingest / jobs / entities / data）、
              启动自检、单实例锁、SQLite 适配层与迁移、词表播种、配置加载、
              记录/搜索/备份恢复/整理与隐私/修正层/关系图谱各服务
src/shared/   契约层：封闭枚举（constants/enums.json）、情绪与主题词表
              （vocab/）、Zod Schema 与 DTO、ID 前缀、CJK 分词器、契约指纹加载
src/web/      React 19 + Vite 7 前端（可视化层，不持有业务数据）：
              三 tab 外壳与今天 / 盒子 / 记录 / 搜索 / 数据 / 睡前 / 更多各面板，
              可读投影与两个数据口（真接口 productPort / 演示 fixturePort）
scripts/      开发启动器：dev.mjs 纯本地、launch.mjs 会注入仓库外的模型 key、
              mock-web.mjs 拉起 5174 的演示界面；三个都是 node 脚本，跨系统同一条命令
fixtures/     演示数据（mock 模式，仅 dev 构建被引用）
tests/        vitest 验收断言（一律使用隔离数据目录，不触碰真实用户数据）
```

## 本地 API 面

前端与后端之间的全部接口，都是本机的、无鉴权的回环 HTTP（单用户应用的明确取舍）：

```
GET  /api/health                        自检摘要（版本、契约指纹、数据目录、绑定地址）
POST /api/records                       写一条（带处理模式）
GET  /api/records?limit&offset          列表
GET/PUT/DELETE /api/records/:id         读 / 改原文（产生新版本）/ 硬删除
PATCH /api/records/:id/mode             改这条的处理模式（状态随之迁移）
GET  /api/search?q=                     全文检索
POST /api/search/rebuild                索引重建（先报失步，再报重建后）
GET  /api/ingest/pending                待整理队列
POST /api/ingest/parse                  跑一次整理（本机或云端 Provider）
POST /api/ingest/preview                取真实待发文本（脱敏预览）
POST /api/ingest/confirm-send           逐条本次发送授权（写入授权账本）
POST /api/ingest/adopt | /discard       采纳 / 丢弃一次整理结果
POST /api/ingest/undo-adopt             撤回采纳
GET  /api/ingest/review-queue           复核队列（只读投影，可批量确认）
GET/PUT /api/ingest/config              模型与隐私模式（两档：本机 / 云端）
PATCH /api/ingest/config/processing     改这条的处理模式档（整理方式）
POST /api/ingest/config/test            云端连通性自测
POST /api/ingest/local-llm/test         本地模型可达性自测
GET  /api/jobs?recordId=                后台任务观测面（轮询进度）
POST /api/jobs/:id/cancel               取消在途任务
GET  /api/entities/vocabulary           词表与候选实体
POST /api/entities/promote              转正候选实体为正式实体
POST /api/backups                       建快照
GET  /api/backups                       列表 + 磁盘余量
POST /api/backups/:name/verify          校验快照
DELETE /api/backups/:name               删快照
POST /api/restore                       整库替换（必须 confirm=true，替换前先做安全备份）
GET  /api/export/jsonl                  全量导出 NDJSON
POST /api/import/jsonl                  导入（目标非空即 409 拒绝）
GET  /api/data-check                    数据一致性自检
GET  /api/storage-maintenance[/retry]   存储维护待办与重试
```

错误响应只带错误码与策展过的说明，不回显输入原文，也不透出 SQL 细节。
